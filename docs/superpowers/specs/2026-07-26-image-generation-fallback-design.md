# 图片生成自动降级设计

## 背景与目标

第三方图片生成供应商存在超时、限流、服务不可用和空结果等临时故障。当前任务遇到这些错误会直接失败，即使系统中已经配置了其他可用公共模型。

本方案采用“任务内顺序降级”：用户选择的模型仍是主模型；主模型发生可降级故障时，后端按管理员指定顺序尝试备用模型。任一备用模型成功后，任务按成功完成并展示图片，同时明确告知用户本次使用了降级方案。

目标：

- 临时供应商故障时尽可能产出图片。
- 不掩盖内容审核、参数错误、密钥错误、无权限和余额不足等问题。
- 普通用户只看到安全提示，管理员通过结构化日志定位原因。
- 覆盖后台单张、模板批量和普通批量任务，兼容现有同步接口。
- 备用链和任务状态均不持久化 API Key。

第一版不实现自动熔断、健康看板，也不改造现有后台任务的进程重启恢复机制。

## 管理员配置

`image_model_configs` 增加：

- `fallback_enabled: bool`：是否允许作为备用模型，默认 `false`。
- `fallback_priority: int | null`：备用顺序，数值越小越优先。
- `capabilities: json`：管理员声明的模型能力。

`sort_order` 继续只控制列表展示顺序，不承担降级语义。

能力字段第一版支持：

- `text_to_image`
- `single_reference`
- `multiple_references`
- `image_edit`
- `mask_edit`
- `aspect_ratios`，空数组表示供应商自行适配比例

新增模型时按 `provider_type` 提供保守默认值，管理员可以修改。未知能力默认不参与对应任务的降级，不能抱着“试试看”的方式调用。

公共模型管理界面增加：

- “允许作为备用模型”开关。
- 启用后显示“降级优先级”数字输入。
- 能力复选框及支持比例设置。
- 模型列表显示“备用 1”“备用 2”等标记。

约束：

- 只有启用中的公共模型可以作为备用模型。
- 系统默认模型可以同时作为备用模型。
- 当前主模型从候选列表中排除，避免重复调用。
- 相同优先级按 `sort_order`、创建时间稳定排序。
- 停用或删除模型后自动退出备用候选列表。
- 内置引擎第一版可以作为主模型，但不能被管理员加入备用链；备用链只使用公共模型配置。

## 统一模型引用与密钥边界

任务不再保存完整运行时模型配置，而保存安全的统一引用：

```json
{
  "source": "builtin | config | system_default",
  "provider": "gemini | gemini_ch | gpt_image | doubao | null",
  "config_id": "uuid | null",
  "display_name": "用户可见名称"
}
```

解析规则：

- 用户选择公共模型时，主引用为 `config` 和对应 `config_id`。
- 用户选择内置引擎时，主引用为 `builtin` 和对应 `provider`。
- “跟随系统默认”在任务创建时解析为当时实际生效的公共默认模型；没有公共默认时解析为环境变量配置的内置默认引擎。
- 匿名用户使用同样的系统默认解析规则。
- 公共模型候选列表在任务创建时只快照模型 ID 和安全名称；实际执行和重试时重新读取数据库，已停用或删除的候选会被跳过。

公共模型 API Key 只允许在执行阶段通过独立数据库会话读取并形成短生命周期运行时配置。以下位置不得出现 API Key、Base URL 或完整第三方错误体：

- `batch_tasks.shared_config`
- `batch_task_items`
- 任务状态响应
- SSE、下载和重试响应
- 普通应用日志

现有 `runtime_config()` 进入 `shared_config` 的链路必须改为模型引用。数据库迁移同时清理历史 `batch_tasks.shared_config.image_model_config.api_key` 和 `base_url`，避免旧任务继续保留密钥。

内置引擎凭据仍从环境变量读取，不写入任务。

## 降级协调器

新增独立的图片生成降级协调器。它负责：

- 解析主模型和备用候选。
- 根据任务能力筛选候选。
- 调用现有供应商适配器。
- 判断错误是否允许降级。
- 返回图片和安全的降级元数据。

`PosterService` 继续负责提示词构造、品牌包叠加、保存文件和作品库写入。降级协调器只包围“第三方生成并取得有效图片”阶段。本地保存、品牌叠加和数据库提交发生在降级链之后；这些步骤失败时不得调用下一个模型。

运行流程：

1. API 创建任务，保存主模型引用和备用模型安全引用。
2. 后台任务根据当前模式计算所需能力。
3. 协调器调用主模型。
4. 若出现允许降级的故障，按优先级筛选并调用备用模型。
5. 候选能力不匹配、已停用或已删除时跳过并记录安全日志。
6. 任一备用模型成功并返回有效图片后立即停止。
7. 所有候选失败后，任务保持失败状态并允许重试。

所有尝试复用同一提示词、宽高比、参考图、蒙版和品牌输入。备用模型不能满足原始尺寸但支持同一宽高比时，允许由现有保存流程统一输出；宽高比本身不支持时跳过。

## 供应商错误契约

当前适配器把多种失败都压缩为 `None`，无法安全降级。各供应商适配器改为抛出统一的 `ImageGenerationError`：

- `category`
- `retryable`
- `provider_status`
- `safe_message`
- `internal_code`

分类优先级：

1. 先解析供应商业务错误码、余额/配额字段、审核字段和结束原因。
2. 再参考 HTTP 状态。
3. 最后参考网络异常类型。
4. 无法可靠分类时设置 `retryable=false`。

允许自动降级：

- 网络连接失败。
- 请求超时。
- 明确的临时限流 `429`。
- HTTP `500`、`502`、`503`、`504`。
- 明确成功且未触发审核，但没有图片数据。
- 第三方图片 URL 下载超时、下载失败、非图片响应或图片解码失败。

禁止自动降级：

- 内容审核、安全策略拒绝或供应商安全结束原因。
- 参数、提示词、蒙版、尺寸或能力不支持。
- API Key 错误、无访问权限。
- 余额不足、账号欠费、日/月配额耗尽；即使供应商使用 `429` 也不降级。
- 用户主动取消。
- 本地保存、品牌叠加、数据库写入等内部错误。

`asyncio.CancelledError` 必须原样向上抛出，任何阶段收到取消后不再尝试候选模型。

## 任务状态、持久化与接口

`batch_task_items` 增加：

- `degraded: bool`，默认 `false`
- `requested_model_name: str | null`
- `actual_model_name: str | null`
- `fallback_attempts: int`，默认 `0`

`BatchItemStatus`、任务序列化和同步生成响应增加同名安全字段。历史任务缺少字段时使用 `false`、`null` 和 `0`。

批量任务中：

- 每张图片卡片单独显示是否降级及实际模型。
- 顶部显示“其中 N 张使用备用模型”的汇总。

降级成功时提示：

> 当前图片由备用模型生成，效果可能与所选模型不同。如有问题，请联系管理员查看原因。

并显示：

> 原选择：主模型名称 · 实际生成：备用模型名称

正常成功不显示提示。全部失败沿用现有失败卡片和重试按钮。

任务中的 `error_message` 只能保存固定的安全错误文案；完整异常只进入脱敏结构化日志。状态接口不得继续返回 `str(exc)`。

重试规则：

- 仅在当前单进程任务仍存在时支持重试，保持现有系统能力边界。
- 重试从任务创建时的主模型引用开始。
- 备用候选按重试时数据库中的启用状态和最新优先级重新解析。
- 重试接口补充当前用户和数据库依赖；登录任务只允许任务所有者或管理员操作。
- 匿名任务第一版维持现有随机 UUID 隔离，不新增进程重启恢复保证。

现有部署已经固定为单 worker，第一版明确不承诺服务重启后恢复含参考图的任务。后续如需恢复，必须把运行时图片迁移到带生命周期的对象存储并实现数据库任务领取机制，该工作不属于本次降级功能。

## 日志与安全

每条降级链生成关联 ID。使用现有结构化 logger，禁止使用 `print`。日志记录：

- 任务 ID、子项 ID、用户 ID。
- 主模型 ID、供应商类型和模型名称。
- 每次失败的错误分类、HTTP 状态和耗时。
- 被跳过的模型及能力不匹配原因。
- 实际成功模型、总尝试次数和最终状态。

日志不得记录 API Key、Base URL、完整图片 Base64、完整第三方响应体或完整提示词。普通用户界面不展示内部错误详情。

状态、重试和下载接口至少对登录任务执行所有者/管理员校验。本次修改涉及的接口必须增加越权测试。

## 数据库迁移与兼容

- 新模型字段使用安全默认值，现有模型不会自动成为备用模型。
- 管理员手动选择至少一个备用模型后降级才生效。
- 未配置备用模型时，行为与当前系统一致。
- 新任务只保存安全模型引用。
- 迁移脚本清除历史任务 JSON 中的模型 Key 和 Base URL。
- 已存在但无法恢复运行时图片的历史任务不自动重启。

## 测试策略

模型解析与配置：

- 公共模型、内置主模型、系统默认和匿名任务均生成正确安全引用。
- 候选按优先级稳定排序、排除主模型并跳过停用/删除项。
- 管理员备用开关、优先级和能力配置正确校验。
- 任务 JSON、子项、API 响应和日志均不包含 Key、Base URL 或第三方响应体。
- 历史任务 JSON 清理迁移生效。

错误分类与执行：

- 连接失败、超时、临时 429、5xx、有效空结果和图片下载失败触发下一模型。
- 429 配额耗尽、审核拒绝、401/403、参数错误、能力错误和未知异常立即终止。
- Gemini 安全结束不会被误判为普通空结果。
- 取消发生在主调用、候选之间或下载阶段时均停止降级。
- 非图片响应、无效 Base64、解码失败和下载超时正确分类。
- 本地保存、品牌叠加和作品库提交失败时不调用备用模型。

任务与接口：

- 自定义、模板、普通批量以及支持相应能力的改图模式使用同一协调器。
- 备用成功后持久化并返回正确安全元数据。
- 批量混合结果逐项提示并显示汇总数量。
- 全部失败后保留重试能力。
- 重试重新读取最新备用顺序，但仍从原主模型引用开始。
- 历史任务状态兼容缺失字段。
- 登录任务状态、重试和下载接口拒绝越权访问。

前端：

- 仅管理员可配置备用开关、优先级和能力。
- 降级成功显示提示及主/实际模型名称。
- 正常成功不显示提示。
- 批量结果显示逐项标记和顶部汇总。
- 全部失败仍显示现有重试按钮。
