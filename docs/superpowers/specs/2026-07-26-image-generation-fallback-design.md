# 图片生成自动降级设计

## 背景与目标

第三方图片生成供应商存在超时、限流、服务不可用和空结果等临时故障。当前任务遇到这些错误会直接失败，即使系统中已经配置了其他可用公共模型。

本方案采用“任务内顺序降级”：用户选择的模型仍是主模型；主模型发生可降级故障时，后端按管理员指定的顺序尝试备用模型。只要任一备用模型成功，任务按成功完成并展示图片，同时明确告知用户本次使用了降级方案。

目标：

- 临时供应商故障时尽可能产出图片。
- 不掩盖内容审核、错误参数、错误密钥和余额不足等需要处理的问题。
- 普通用户只看到安全、可行动的提示。
- 管理员能够从日志定位主模型失败原因和实际使用的备用模型。
- 保持现有后台单张、模板批量和普通批量任务行为兼容。

## 管理员配置

`image_model_configs` 增加：

- `fallback_enabled: bool`：是否允许作为备用模型，默认 `false`。
- `fallback_priority: int | null`：备用顺序，数值越小越优先。

`sort_order` 继续只控制模型列表展示顺序，不承担降级语义。

公共模型管理界面增加：

- “允许作为备用模型”开关。
- 启用备用后显示“降级优先级”数字输入。
- 模型列表显示“备用 1”“备用 2”等标记。

约束：

- 只有启用中的公共模型可以作为备用模型。
- 系统默认模型可以同时作为备用模型。
- 当前主模型必须从候选列表中排除，避免重复调用。
- 相同优先级按现有 `sort_order`、创建时间稳定排序。
- 停用或删除模型后自动退出备用候选列表。

## 运行时流程

新增独立的图片生成降级协调器，负责选择候选模型、执行尝试和生成安全的结果元数据。具体供应商调用仍由现有 `PosterService` 完成。

1. API 创建任务时记录用户选择的主模型 ID。
2. 后台任务开始生成时，从数据库读取当前主模型和启用的备用模型。
3. 先调用主模型。
4. 如果失败被判定为可降级故障，按 `fallback_priority` 依次调用备用模型。
5. 任一备用模型成功后立即停止尝试，正常保存图片。
6. 所有候选模型失败后，任务保持失败状态并允许用户重试。

备用模型配置在执行时从数据库解析，任务状态和接口响应不得持久化或返回 API Key。每次尝试复用同一提示词、宽高比、参考图、蒙版和品牌包输入。

对于供应商不支持当前能力的情况，例如备用模型不支持多参考图、蒙版或指定尺寸，协调器在调用前跳过该模型并写入管理员日志，不把它计为一次第三方失败。

## 故障分类

允许自动降级：

- 网络连接失败。
- 请求超时。
- HTTP `429`。
- HTTP `500`、`502`、`503`、`504`。
- 第三方返回成功状态但没有有效图片。
- 第三方图片 URL 下载失败或内容不是有效图片。

禁止自动降级：

- 内容审核或安全策略拒绝。
- 请求参数、提示词或尺寸不合法。
- API Key 错误或无访问权限。
- 余额不足、配额耗尽或账号欠费。
- 用户主动取消。
- 本地保存图片、数据库写入等系统内部错误。

供应商适配层应抛出结构化错误，至少包含：

- `category`
- `retryable`
- `provider_status`
- `safe_message`

无法可靠分类的异常默认不降级，避免掩盖配置或代码问题。

## 任务状态与接口

单个生成项增加安全元数据：

- `degraded: bool`
- `requested_model_name: str | null`
- `actual_model_name: str | null`
- `fallback_attempts: int`

普通用户的任务状态接口不返回第三方响应体、Base URL、模型密钥或完整异常。

降级成功时，前端在结果图片上方展示非阻断提示：

> 当前图片由备用模型生成，效果可能与所选模型不同。如有问题，请联系管理员查看原因。

同时显示：

> 原选择：主模型名称 · 实际生成：备用模型名称

非降级成功时不显示额外提示。全部失败时沿用当前失败卡片和“重试失败项”按钮。

失败重试从用户当前选择的主模型重新开始，再按最新管理员备用顺序执行，避免永久绑定到上一次备用模型。

## 日志与可观测性

每次降级链生成一个关联 ID。管理员日志记录：

- 任务 ID、子项 ID和用户 ID。
- 主模型 ID、供应商类型和模型名称。
- 每次失败的安全错误分类、HTTP 状态和耗时。
- 被跳过的备用模型及能力不匹配原因。
- 实际成功模型和总尝试次数。
- 最终成功或失败。

日志不得记录 API Key、完整图片 Base64、完整第三方响应体或敏感提示词。普通用户界面不展示内部错误详情。

第一版不实现自动熔断、健康检查面板和供应商成功率统计。后续调用量增大后，可以基于结构化日志增加短时熔断。

## 数据库迁移与兼容

- 新字段使用安全默认值，因此现有模型不会自动成为备用模型。
- 管理员需要手动选择至少一个备用模型，降级才会生效。
- 未配置备用模型时，行为与当前系统一致。
- 历史任务缺少降级字段时，序列化层使用 `false`、`null` 和 `0` 作为默认值。
- 多进程部署下候选模型从数据库读取，不依赖进程内共享配置。

## 测试策略

后端单元测试：

- 候选模型按优先级稳定排序并排除主模型。
- 可降级故障触发下一模型。
- 禁止降级错误立即终止。
- 空结果和图片下载失败触发降级。
- 不支持当前能力的备用模型被跳过。
- 备用成功后返回正确安全元数据。
- 所有模型失败后保留重试能力。
- 日志与接口不泄露 Key、Base URL 和第三方响应体。

API 与任务测试：

- 单张自定义、以图改图、模板生成和批量生成均使用相同降级协调器。
- 历史任务状态兼容缺失字段。
- 重试时重新读取最新备用顺序。

前端测试：

- 仅管理员可配置备用开关和优先级。
- 降级成功显示提示和主/实际模型名称。
- 正常成功不显示降级提示。
- 全部失败仍显示现有重试按钮。
