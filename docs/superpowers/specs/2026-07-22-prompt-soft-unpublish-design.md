# 提示词公共广场软撤回设计

## 目标

允许提示词所有者将已发布内容从公共广场撤回，同时保留个人收藏、内容、使用次数和已产生的 Fork 副本。

## 后端

- 新增 `POST /api/v1/prompts/{prompt_id}/unpublish`。
- 仅提示词所有者可撤回；不存在或无权操作统一返回 `404`。
- 仅将原记录的 `is_public` 更新为 `false` 并刷新 `updated_at`，不删除记录、不修改 `is_active` 和 `use_count`。
- 已 Fork 的提示词是独立记录，不随原提示词撤回而变化。
- 公共列表继续只查询 `is_public=true`，所以撤回后原记录立即从广场消失；个人列表仍按 `user_id` 查询，因此记录继续保留。

## 前端

- 提示词卡片接收当前用户 ID，并计算是否为所有者。
- 仅所有者可看到编辑、删除、发布和撤回操作；其他用户的公共卡片不显示这些管理操作。
- 所有者对公开提示词看到“撤回广场”，对私有提示词看到“发布共享”。
- 撤回前显示确认弹窗，说明只会从广场移除，不会删除个人收藏和历史数据。
- 撤回成功后重新加载当前列表；在公共广场中卡片自然消失，在我的收藏中变为私有。
- 请求失败时保留当前列表并显示后端错误。

## 验证

- 服务测试覆盖所有者软撤回、非所有者拒绝、状态与统计数据保留。
- API 测试覆盖撤回接口与错误响应。
- 前端测试覆盖 API 方法、所有者操作可见性和撤回确认流程。
- 运行后端全量测试、前端全量测试、生产构建和 `git diff --check`。
